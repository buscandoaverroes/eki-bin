# v1.4 gift-jar system — XIAO + LED strip + power

**Status: ⬜ Proposed** — wiring matches the bring-up findings in
`docs/hardware.md` and the board pinout below, but the strip's GND pad
position (⚠ below) needs a physical confirm before this flips to ✅.

**A "system" file, not a board file.** Every other file in this directory
documents one board's own pins (`pico2w.md`, `xiao_esp32c3.md`). This one
documents how the **v1.4 gift-jar build's few parts connect to each other**
— the board pinout is still the single source of truth for the XIAO's own
pin numbers; this file is the assembly on top of it. Add a new file in this
shape for a future build with a meaningfully different part set (e.g. a
different MCU, a second LED run, a sensor added) — don't grow this one to
cover everything.

Parts (3 total — this build is deliberately minimal):
1. **Seeed XIAO ESP32-C3** — own pinout: [xiao_esp32c3.md](xiao_esp32c3.md)
2. **WS2812B LED strip**, cut to 21 LEDs — parts/bring-up: `docs/hardware.md`
3. **USB-C power in** — either a wall/USB adapter directly, or a Qi wireless
   receiver's USB-C output — see `docs/hardware.md`'s Qi bring-up log

## The assembly

Only two power sources, both landing on the same XIAO USB-C port — they're
interchangeable, not simultaneous:

```
  [Wall / USB-C adapter]         [Qi charging pad]
            │                            │ (wireless)
            │                            ▼
            │                   [Qi WCR — USB-C out]
            │                            │
            └──────────────┬─────────────┘
                            ▼
                   XIAO ESP32-C3 (USB-C in)
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
             5V            GND        D0 / GPIO2
              │             │             │
              └──────┬──────┴──────┬──────┘
                     ▼             ▼
         WS2812B strip input pigtail (3-pin)
```

Only 3 wires leave the XIAO — same "3 connections" pattern every board file
in this directory already uses for the LED stick, just now feeding a strip
instead:

| XIAO C3 | GPIO (for `config.py`) | → | Strip input pigtail |
|---|---|---|---|
| 5V | — | → | 5V |
| GND | — | → | ⚠ see below |
| D0 | `2` | → | DI (data in) |

**`config.py` values**: `LED_PIN = 2` (matches `xiao_esp32c3.md`)

## Strip input pigtail — pad order

Confirmed from the physical strip: **held with the LEDs facing DOWN**, the
input pigtail reads, top to bottom:

1. **5V**
2. ⚠ *(not yet confirmed which pad — see below)*
3. **DI** ← XIAO D0/GPIO2

⚠ **Open:** only 5V (top) and DI (bottom) were confirmed against the physical
part; the middle pad is presumed GND (the only remaining wire of the 3, and
the conventional 5V/GND/DATA pigtail order most WS2812B strips use) but
**this hasn't been physically verified** — flagging per this directory's own
convention (an unverified guess stated as fact costs a bring-up session; a
flagged unknown costs five minutes with a multimeter). Confirm against the
actual pigtail, then flip this file's status to ✅ and remove the flag.

## Power source notes

- **Wall/USB-C adapter** — direct, no intermediate hardware. Used for dev
  bring-up and testing (see `config_friend1.py`'s WiFi-swap-last-step note —
  same idea: dev power now, final power path at handoff).
- **Qi wireless receiver (WCR)** — bare unbranded board, 5V/1A in (wireless)
  → 5V/800mA out (USB-C), confirmed no foreign-object-detection rejection on
  a Belkin pad, confirmed working through glass (simulating the jar wall).
  Full bring-up: `docs/hardware.md`'s 2026-07-13 log.
- **Known ceiling:** `BRIGHTNESS = 1.0` (full white, 120-LED tape) froze the
  Qi path and tripped USB overcurrent on direct power too — `docs/hardware.md`
  documents the safe ceiling found for that strip length. This 21-LED gift
  build's own tuned ceiling lives in `config_friend1.py` (gitignored), not
  here — this file is wiring, not brightness tuning.
